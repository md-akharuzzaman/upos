# eURC POS v2.3.2 — keep database connections open

CD #5 (v2.3.1) failed in **test** twice: one request per run took 15 s
(a sign-in, a refund) and the integration test gave up at 15 s. Application
Insights showed Blob and Key Vault calls were fast and the database was almost
idle (DTU max 2 %); the time went into opening new SQL connections to the
database in Mexico Central (managed-identity token, TLS, gateway redirect):
3-4 new connections per run because the pool closed every connection after
30 s idle, and the identity endpoint itself took 5-6 s at times.

| Change | Detail |
|---|---|
| SQL connection pool | Keeps at least 2 connections open; idle ones close after 10 min instead of 30 s. Requests no longer pay connection set-up after a quiet spell. |
| Test HTTP timeout | 15 s → 30 s, the same as the API's SQL request timeout. Slow responses are still caught by the load gate (p95 < 3 s). |

No database or UI changes.
