# eURC POS v2.3.1 — release safety: swap with preview

v2.3.0 passed dev, test and the staging-slot smoke test, but the swap into
production failed (CD #4): *"Cannot swap slots ... application initialization
in 'staging' slot either took too long or failed. ... try using swap with preview"*.
A swap restarts the staging slot with production's slot settings, and App
Service gives that restart a fixed warm-up time; on S1 with VNet integration,
private endpoints and a database in another region the restart can exceed it
(CD #3 for v2.2 failed the same way and passed on a re-run). Production was not
affected: a failed swap leaves it on the previous version.

| Change | Detail |
|---|---|
| Two-phase swap | `.github/scripts/swap-slots.sh`: **preview** (apply production settings to staging, restart) → **wait** up to 15 min until the staging slot is Healthy with those settings and on the release version (smoke test) → **swap** (the slot is already warm, seconds). Any failure before the switch resets the preview. |
| Rollback | Uses the same two-phase swap. |
| Cancelled runs | A run cancelled mid-preview resets the swap so the next deployment is not blocked. |

No application or database changes; the version is 2.3.1 so the release is
traceable. Prod gets v2.3 features (and fixes the v2.2/Admin rollback caveat:
migration 6 is already applied in prod, so store owners are Admins and v2.2
only lets them sell until v2.3 is live).
