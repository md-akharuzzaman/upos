# eURC POS v2.3.0 — foundations for a supermarket

## What's new

| Area | Change |
|---|---|
| **Roles** | Six roles with a permission matrix: **Admin** (everything, incl. business profile), **Manager** (products, prices, promotions, refunds, reports, staff), **Cashier** (register, sales), **Sales** (register, promotions, reports), **Procurement** (products, stock, categories), **Customer support** (sales look-up, refunds within policy). The person who opens the store is its Admin; managers cannot create or change admins; a store always keeps one active admin. Every API route checks its permission. |
| **Business profile** (Admin) | Legal name, address (Canadian postal code / province), phone, e-mail, website, **GST/HST number** (CRA format 123456789 RT0001), PST and QST numbers, time zone, **store type**, accepted **payment methods** (cash, debit, credit, Interac e-Transfer, Stripe), e-Transfer e-mail, Stripe account. **Bank details** are stored only in Azure Key Vault; the app shows them masked (••••3210). Receipts print the legal name, address and tax numbers. |
| **Store type** | Coffee shop, restaurant, supermarket, convenience, clothing, pharmacy, electronics, general retail. *Add starter categories* creates a matching category tree, with perishables marked final sale. |
| **Categories** | Category → sub-category tree per store, each with a *final sale* default for new products. Searchable drop-downs in the product form, filters, promotions and price changes; promotions on a category also cover sub-categories of that name. |
| **Barcodes** | Barcode per product (EAN-8, UPC-A, EAN-13, GTIN-14 with check digit, or internal codes), unique per store. At the register a USB/Bluetooth scanner (types the code + Enter) adds the product instantly; *Camera* scans with the device camera where the browser supports it. |
| **Expiry dates** | Expiry per product; **expired items cannot be sold**; filters for expired / within 3, 7, 30 days; badges on products and register tiles. |
| **Large catalogues** | Server-side search and paging (register and products), barcode/SKU lookup, Excel import in batches of 1,000 with progress and *Resume*, bulk database inserts, price/tax changes on a whole category in one statement. `scripts/40-bulk-import.mjs` imports a CSV of any size from Cloud Shell (dry run, progress, resume). Rehearsed with a 200,000-product catalogue. |
| **Release safety** | New `/health/ready` (started + schema current). Slot-swap warm-up and the App Service health check use it, so a slow first dependency connection can no longer cancel a swap (CD #3 for v2.2). `/health` still checks SQL, Blob and Key Vault for monitoring and the post-deploy gate. |

## Database

Migration 6: new columns and tables (expand), role CHECK widened, first manager of each store promoted to Admin, indexes for barcode (unique, filtered), category, name and expiry.
Rollback caveat: on v2.2 an Admin is not a "manager" and could only sell until v2.3 is back - roll forward, or set the role back to `manager` in SQL.

## QA script for the test environment

1. **Business** (Admin): legal name, address, GST/HST number, payment methods, store type *Supermarket*, *Add starter categories*, bank details → masked after saving.
2. **Staff**: add one person per role; sign in as each and check the tabs (Support: Sales only; Procurement: Products; Sales: Register, Promotions, Report).
3. **Products → Categories**: see the tree; mark a category final sale.
4. **Products**: add a product with sub-category, barcode `4006381333931` and an expiry date in the past → shown *expired*.
5. **Register**: type/scan `4006381333931` + Enter → added; the expired product cannot be added; category and sub-category chips filter.
6. **Import from Excel** with `supershop-1000-sample.xlsx` → 1,000 new, progress bar; *Products* shows 1–50 of 1,0xx with paging.
7. **Change prices / tax** on a sub-category (e.g. *Cheese*) +5 % → preview shows the first 50 and "and N more".
8. Receipt shows the legal name, address and GST/HST number.
