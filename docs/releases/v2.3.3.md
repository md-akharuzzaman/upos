# eURC POS v2.3.3 — retry a stuck database connection

**Root cause of the CD #5 / CD #6 test failures.** The app's console log showed
`[error] POST /api/sales/.../refund operation timed out for an unknown reason`
30 s after each stuck request. That message comes from the SQL connection
pool (tarn, used by mssql): the request waited 30 s for a database connection
and never got one. Opening a new connection to the database in another region
occasionally hangs - it neither connects nor fails - and with mssql's default
pool settings that single stuck attempt fails the whole request. Reproduced
locally with a pool whose first connection never completes: same error after
the acquire timeout. The database itself was idle (DTU max 2 %), no SQL
connection failed, Blob and Key Vault calls were fast.

| Change | Detail |
|---|---|
| Connection attempts | Each new SQL connection gets 10 s (was 30 s); a stuck attempt is abandoned and the pool tries again. |
| Pool behaviour | `propagateCreateError: false`, `acquireTimeoutMillis: 25000`: a request waits for a working connection (up to 25 s) instead of failing on the first stuck attempt. |
| v2.3.2 (kept) | At least 2 connections stay open, idle ones close after 10 min, so new connections are rarely needed at all. |

No database or UI changes.
